Abstract
========

This PEP allows ``Unpack[TypedDict]`` in the parameter list of ``Callable``.
Its purpose is concise expression, not new keyword-typing semantics:
``Callable[[Unpack[TD]], R]`` is defined to be equivalent to a callback
protocol with ``__call__(self, **kwargs: Unpack[TD]) -> R``.

Motivation
==========

The :ref:`typing specification <typing:callable>` currently states that
``Callable`` cannot directly express keyword-only parameter structure, and
recommends callback protocols for that use case.

This PEP adds a compact ``Callable`` spelling for that existing protocol
pattern.

Rationale
=========

This proposal is intentionally narrow.

It does not redefine ``Unpack`` or ``TypedDict`` behavior. It introduces only
an equivalence rule for ``Callable`` and defers all existing keyword-typing
rules to the typing specification and prior PEPs.

This follows the direction of :pep:`646` (unpacking in ``Callable``) and keeps
scope boundaries consistent with :pep:`612` (no new ``Concatenate`` keyword
composition rules).

Specification
=============

New allowed forms
-----------------

It becomes valid to write::

    Callable[[Unpack[TD]], R]

where ``TD`` is a ``TypedDict``.

Additionally, positional parameters may appear before an unpacked
``TypedDict``::

    Callable[[int, str, Unpack[TD]], R]

Semantics
---------

For type-checking purposes, ``Callable[[Unpack[TD]], R]`` is equivalent to a
callback protocol form::

    class _Proto(Protocol):
        def __call__(self, **kwargs: Unpack[TD]) -> R: ...

Accordingly, semantics are inherited from existing specifications and are not
restated in this PEP:

* typing spec section `Unpack for keyword arguments
  <https://typing.python.org/en/latest/spec/callables.html#unpack-for-keyword-arguments>`_
* :pep:`692` for ``Unpack`` with ``**kwargs``
* :pep:`728` for ``closed`` and ``extra_items``
* :pep:`655` for ``Required`` and ``NotRequired``

This PEP adds only the following ``Callable``-specific rules:

* ``Unpack[TD]`` may appear in ``Callable`` parameter lists.
* Positional parameters may appear before ``Unpack[TD]`` in ``Callable``.
* An unpacked ``TypedDict`` may substitute a ``ParamSpec`` in
  ``Callable[P, R]`` contexts.
* Using ``Unpack[TD]`` inside ``Concatenate`` is not supported by this PEP.

Examples
========

Protocol equivalence
--------------------

::

    from typing import Any, Callable, Protocol, TypedDict, Unpack

    class KeywordTD(TypedDict):
        a: int

    type KwCallable = Callable[[Unpack[KeywordTD]], Any]

    class KwCallableProto(Protocol):
        def __call__(self, **kwargs: Unpack[KeywordTD]) -> Any: ...

Callable-specific compatibility behavior
----------------------------------------

::

    from typing import Any, Callable, TypedDict, Unpack

    class KeywordTD(TypedDict):
        a: int

    type IntKwCallable = Callable[[Unpack[KeywordTD]], Any]

    def normal(a: int): ...
    def kw_only(*, a: int): ...
    def pos_only(a: int, /): ...

    f1: IntKwCallable = normal   # Accepted
    f2: IntKwCallable = kw_only  # Accepted
    f3: IntKwCallable = pos_only # Rejected

Backwards Compatibility
=======================

This feature is additive and typing-only.

Subscripting a runtime ``ParamSpec``-based alias with generic
``Unpack[TypedDict]`` currently requires extra brackets in some cases; a
``TypeAliasType`` alias is not affected::

    from typing import Callable, ParamSpec, TypedDict, TypeAliasType, Unpack

    class Config[T](TypedDict):
        setting: T

    type CallP1[**P] = Callable[P, None]
    CallP1_Subbed = CallP1[Unpack[Config[int]]]      # OK

    P = ParamSpec("P")
    CallP2 = Callable[P, None]
    CallP2_A = CallP2[[Unpack[Config[int]]]]         # OK
    CallP2_B = CallP2[Unpack[Config[int]]]           # currently TypeError

How to Teach This
=================

This feature is a shorthand for Protocol-based callbacks. Users should be
taught that with ::

    class KeywordTD(TypedDict):
        a: int
        b: NotRequired[str]

* ``Callable[[Unpack[KeywordTD]], R]`` is equivalent to defining a Protocol with
  ``__call__(self, **kwargs: Unpack[KeywordTD]) -> R``
  (and therefore follows existing ``Unpack[TypedDict]`` rules).
* Teachers might want to introduce the concept of ``TypedDict`` with
  ``Callable`` first before introducing ``Protocol``.

Therefore it follows existing ``Unpack[TypedDict]`` semantics from the
typing spec introduced by :pep:`692` and :pep:`728`, rather than introducing
new keyword typing rules.


Reference Implementation
========================

A prototype exists in mypy:
`python/mypy#16083 <https://github.com/python/mypy/pull/16083>`__.

Rejected Ideas
==============

Combining ``Unpack[TD]`` with ``Concatenate``
---------------------------------------------

This PEP does not support forms like
``Callable[Concatenate[int, Unpack[TD], P], R]``.

Supporting this would expand scope beyond a shorthand-equivalence proposal and
requires additional rules around interactions between positional and keyword
composition (see :pep:`612`).

Open Questions
==============

* Should multiple ``TypedDict`` unpacks be allowed in one ``Callable``
  parameter expression, and if so, under which merge rules?
* Should ``Callable[Unpack[TD], R]`` be accepted in addition to
  ``Callable[[Unpack[TD]], R]``?
